## High severity

1. **[DONE 2026-08-25]** **A fast Riot Client restart can leave the tracker using obsolete lockfile credentials forever.**
   The session and websocket task retain one cloned lockfile. Reconnection checks only whether the path exists, not whether its PID, port, or password changed. If Riot replaces the lockfile before the existence check, the websocket retries the old endpoint indefinitely, `run_session` never ends, and the top-level loop never re-reads authentication.
   `app_state.rs:408,415,426`, `local_api.rs:30`

2. **[DONE 2026-08-25]** **Transient enrichment failures are published and cached as successfully "final".**
   Competitive-update, match-detail, and loadout errors are swallowed, after which `cache.enriched` is unconditionally set. The fully cached path then prevents another attempt for the lobby. Violates the IPC guarantee that `enriched: true` nulls represent genuine absence. A partial match-details result is additionally written to the session cache and stays wrong until that player gets a newer competitive match.
   `app_state.rs:861,905,911,921,678`

3. **[DONE 2026-08-25]** **429/auth recovery does not cover all Riot endpoints or the documented error cases.**
   Only name, MMR, competitive-update, match-detail, and loadout calls use the 429 wrapper. Coregame/pregame match-id and match calls are direct (and the 1s pregame poll hits exactly those). Generic 401/non-OK responses become `Http`, not token-refresh signals, despite the spec requiring header refresh after non-OK/BAD_CLAIMS. The fixed six-second retry ignores `Retry-After` and does not refresh tokens on 429.
   `remote_api.rs:91,153`, `app_state.rs:603,613,743`

4. **[DONE 2026-08-25]** **One transient build error can stop rebuilding for the rest of Pregame or Menus.**
   `NotReady` and generic errors return without scheduling a retry. Waiting is timer-bounded only if the published snapshot already says `Pregame`; an initial Pregame failure while the published status is Menus/not-running waits indefinitely for another qualifying websocket event. Ingame recovery similarly depends on a later own-presence event.
   `app_state.rs:470,494,512`

5. **[DONE 2026-08-25]** **Malformed match payloads silently become valid empty lobbies and can poison the match cache.**
   Both match extractors convert deserialization failure into empty/default data; orchestration then finishes enrichment and marks the match fresh. Later valid responses can supply players, but phase-one names/MMR are skipped because the cache is considered complete. Missing `PlayerIdentity` also defaults privacy flags to false — unsafe degradation for incognito handling.
   `match_state.rs:64,113,154`, `app_state.rs:632`

6. **[DONE 2026-08-25]** **The version-keyed static cache can be permanently incomplete for an entire patch.**
   Static fetches call `.json()` without checking HTTP status or validating completeness. If `/version` succeeds but agents/maps/tiers/weapons returns a JSON 429/error body, empty mappings are saved under the valid version and loaded on every start. The authoritative presence version updates only remote request headers; it does not re-key/refetch static data, so a lagging valorant-api version can load stale patch data.
   `static_data.rs:280,300,320`, `app_state.rs:355,547`

## Medium severity

1. **Enrichment cancellation is not prompt while a request or 429 sleep is in flight.** Checked only between requests; a transition can block ~15s (HTTP timeout) to ~36s (timeout + backoff + retry). Phase one is not interruptible at all. `remote_api.rs:51`, `app_state.rs:853,897`
2. **Fast snapshots can contain partial heavy fields.** Same-match rebuilds, Pregame→Ingame upgrades, interrupted enrichment, and BAD_CLAIMS retries preserve cached phase-two fields, so an `enriched: false` snapshot may carry stats for some rows, contrary to the two-phase contract. `app_state.rs:265,649,699`
3. **[DONE 2026-08-25 — wording fixed in ipc-contract.md]** HS% and KD do not obey the documented null coupling. Computed independently: a player with a stats entry but zero recorded hits can produce `headshotPercent: null` with `kd: 0`. Fix code or wording. `stats.rs:111,122,134`
4. **Match-details downloads are cached per player, not per match payload.** The same ~500 KB match response is re-downloaded when lobby players share a recent match (~15 MB per full lobby; a match-id payload cache could cut the best overlapping case from 30 downloads to 3). `app_state.rs:870,884,905`
5. **Every Ingame own-presence event performs two glz GETs before checking freshness.** Roster/map/agents are effectively immutable in-game, so these normally produce an identical deduped snapshot — the main steady-state remote-request waste. `app_state.rs:599,610,630`
6. **Unrelated friends' presence events add unbounded Pregame rebuilds.** Any non-own Valorant presence is `Other` and triggers Pregame work, on top of the 1s poll. `websocket.rs:53`, `app_state.rs:168`
7. **[DONE 2026-08-25 — false positive; hold-last-match documented in ipc-contract.md]** Frontend "violates the Menus IPC layout guarantee" by holding the last match table. Intentional feature; update `docs/ipc-contract.md` to document it. `App.tsx:35,59`
8. **[DEFERRED to release prep]** Release tags are not validated and releases do not run Rust tests; any `v*` tag publishes. `release.yml:6,46`

## Request-rate envelope (worst-case, designed baseline)

| State | Local Riot GETs | glz | pd |
|---|---:|---:|---:|
| Menus steady-state | 0 | 0 | 0 |
| Menus per own/reconnect event | +1 | 0 | 0 |
| Pregame timer-only, 60s | ≤60 | ≤120 | 0 after cache enriched |
| Pregame first 5-player burst | +1 token refresh | (above) | ≤26 |
| Ingame first 10-player lobby | 2 | 3 | 51 |
| Ingame post-enrichment, N own events/min | N | 2N | 0 |

- A Pregame 404 race can raise timer-only glz attempts from 120 to 180/min.
- An all-uncached Ingame burst can attempt up to 102 pd calls with retries (spread by 6s backoffs).
- The 120 ms spacing caps bursts at ~8.33 req/s; no global limiter across repeated lobby transitions.
- Full-lobby traffic ≈ 15 MB of match-detail JSON (see medium #4).
- Endpoint paths and header conventions otherwise match the reference docs.
